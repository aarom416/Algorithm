# 비트마스킹

## 1. 비트마스킹이란?

비트마스킹은 정수의 이진수 비트를 이용해 여러 개의 상태를 하나의 숫자에 저장하는 방법이다. 각 비트를 하나의 선택 여부나 방문 여부로 사용할 수 있다.

예를 들어 4개의 원소를 선택했는지 표현한다고 하자.

```text
비트 위치:  3 2 1 0
상태:       0 1 0 1
            ↑   ↑
          선택 선택
```

이 상태는 0번과 2번 원소가 선택되었다는 의미이다. 이진수 `0101`은 10진수 `5`로 표현할 수 있으므로 상태 전체를 정수 하나로 저장할 수 있다.

## 2. 기본 비트 연산

아래 연산자는 숫자를 이진수로 바꾼 뒤, 같은 위치의 0과 1을 비교하거나 위치를 옮긴다.

- `a & b`: **두 숫자의 같은 위치가 모두 1일 때만 1로 만들어라.**
- `a | b`: **두 숫자의 같은 위치 중 하나라도 1이면 1로 만들어라.**
- `a ^ b`: **두 숫자의 같은 위치가 서로 다르면 1로 만들어라.**
- `~a`: **a의 모든 0과 1을 반대로 바꿔라.**
- `a << n`: **a의 비트를 왼쪽으로 n칸 옮겨라.** 일반적으로 `2^n`을 곱하는 효과가 있다.
- `a >> n`: **a의 비트를 오른쪽으로 n칸 옮겨라.** 일반적으로 `2^n`으로 나누는 효과가 있다.

```java
int a = 0b0101; // 이진수 0101, 10진수 5
int b = 0b0011; // 이진수 0011, 10진수 3

System.out.println(a & b);  // 1: 둘 다 1인 비트만 1
System.out.println(a | b);  // 7: 하나라도 1이면 1
System.out.println(a ^ b);  // 6: 서로 다를 때 1
System.out.println(~a);     // -6: 0101을 반전한 결과
System.out.println(a << 1); // 10: 0101 → 1010, 왼쪽 이동
System.out.println(a >> 1); // 2: 0101 → 0010, 오른쪽 이동
// 전체 출력: 1, 7, 6, -6, 10, 2
```

음수의 비트 반전 결과는 자바의 정수 표현 방식 때문에 직관과 다를 수 있으므로, 코딩 테스트에서는 주로 `&`, `|`, `^`, `<<`, `>>`를 사용한다.

## 3. 특정 비트 켜기·끄기·확인하기

`1 << index`는 **`index`번째 위치를 1로 만들어라**는 뜻이다.

예를 들어 `1 << 2`는 `0001`의 1을 왼쪽으로 2칸 옮기므로 `0100`이 된다. 즉, 2번 위치만 1인 숫자를 만든다.

```java
int mask = 0;
int index = 2;
int bit = 1 << index; // index번째 위치를 1로 만든다. 결과: 0100

mask |= bit;          // mask와 bit를 합쳐서 2번 비트를 1로 만든다. 결과: 0100
boolean selected = (mask & bit) != 0; // 2번 비트가 1인지 확인한다. 결과: true
mask &= ~bit;         // 2번 비트를 0으로 만든다. 결과: 0000
mask ^= bit;          // 2번 비트를 0이면 1로, 1이면 0으로 뒤집는다. 결과: 0100
System.out.println(selected); // true
System.out.println(mask);     // 4: 마지막 XOR로 2번 비트를 다시 켬
```

각 연산의 의미는 다음과 같다.

```text
mask |= bit   → mask에서 해당 위치를 1로 만들기
mask &= ~bit  → mask에서 해당 위치를 0으로 만들기
mask ^= bit   → mask에서 해당 위치를 0과 1 중 반대 값으로 바꾸기
mask & bit    → 해당 위치가 1인지 확인할 수 있도록 꺼내기
```

## 4. 선택 상태 표현하기

원소 `[10, 20, 30]`에서 선택된 원소를 비트마스크로 표현할 수 있다.

```java
int[] numbers = {10, 20, 30};
int mask = 0b101; // 0번과 2번 원소 선택

for (int i = 0; i < numbers.length; i++) {
    if ((mask & (1 << i)) != 0) { // i번째 원소가 선택되었는지 확인
        System.out.println(numbers[i]);
    }
}
// 출력:
// 10
// 30
```

## 5. 모든 부분집합 순회하기

원소가 `n`개라면 부분집합은 총 `2^n`개이다. `1 << n`은 **1을 왼쪽으로 n칸 옮겨서 `2^n`을 만들어라**는 뜻이다. 따라서 `mask`를 `0`부터 `(1 << n) - 1`까지 순회하면 모든 부분집합을 만들 수 있다.

```java
int[] numbers = {1, 2, 3};
int n = numbers.length;

for (int mask = 0; mask < (1 << n); mask++) {
    System.out.print("현재 부분집합: ");

    for (int i = 0; i < n; i++) {
        if ((mask & (1 << i)) != 0) { // i번째 위치가 1인지 확인해 선택된 원소만 출력
            System.out.print(numbers[i] + " ");
        }
    }
    System.out.println();
}
// 출력되는 부분집합: [], [1], [2], [1, 2], [3], [1, 3], [2, 3], [1, 2, 3]
```

`mask = 0`은 공집합이고, `mask = 7`인 `111`은 모든 원소를 선택한 상태이다. 시간 복잡도는 부분집합 수 `2^N`에 각 원소 확인 `N`이 필요하므로 `O(N * 2^N)`이다.

## 6. 선택된 원소의 개수 구하기

```java
int mask = 0b101101;
int count = Integer.bitCount(mask);

System.out.println(count); // 4: 1인 비트의 개수
// 0b101101에서 1인 비트가 4개이므로 출력은 4이다.
```

`Integer.bitCount`는 **정수를 이진수로 봤을 때 1인 비트의 개수**를 세는 함수이다. 즉, 선택된 원소의 개수를 쉽게 구할 수 있다.

## 7. 가장 낮은 비트 확인하기

```java
int mask = 0b101100;
int lowestBit = mask & -mask;

System.out.println(Integer.toBinaryString(lowestBit)); // 100
// 0b101100의 가장 오른쪽 1비트만 남기므로 출력은 100이다.
```

`mask & -mask`는 **가장 오른쪽에 있는 1비트만 남겨라**는 의미로 이해하면 된다. 비트 DP나 부분집합을 빠르게 처리할 때 사용한다.

## 8. 비트마스크와 방문 처리

방문한 정점을 배열 대신 정수 하나로 표현할 수 있다.

```java
static boolean isVisited(int visited, int node) {
    return (visited & (1 << node)) != 0; // node번째 위치가 1인지 확인한다.
}

static int visit(int visited, int node) {
    return visited | (1 << node); // node번째 위치를 1로 만들어 방문 처리한다.
}

int visited = 0;
visited = visit(visited, 2);
System.out.println(isVisited(visited, 2)); // true
System.out.println(isVisited(visited, 1)); // false
// 2번 정점만 방문했으므로 출력은 true, false이다.
```

## 9. 비트마스크와 메모이제이션

외판원 문제처럼 현재 위치와 방문한 도시 목록이 함께 상태가 되는 문제에서는 `dp[현재 위치][방문 상태]` 형태를 사용할 수 있다.

```java
int cityCount = 4;
int[][] dp = new int[cityCount][1 << cityCount]; // 방문 상태가 2^cityCount개이므로 열 크기는 1 << cityCount

for (int i = 0; i < cityCount; i++) {
    Arrays.fill(dp[i], -1);
}

// dp[city][mask]
// city: 현재 위치
// mask: 방문한 도시들의 상태
// 모든 상태의 초기값은 -1이다.
```

도시가 `N`개이면 방문 상태는 `2^N`개이므로 상태 수는 `O(N * 2^N)`이다.

## 10. 이진수 문자열 변환

```java
int number = 13;
String binary = Integer.toBinaryString(number); // 10진수 13을 이진수 문자열로 바꾼다.
System.out.println(binary); // 1101

int restored = Integer.parseInt("1101", 2); // 이진수 문자열을 10진수 정수로 바꾼다.
System.out.println(restored); // 13
// 출력: 1101, 13
```

10진수 정수를 이진수 문자열로 바꾸려면 `Integer.toBinaryString`, 이진수 문자열을 10진수로 바꾸려면 `Integer.parseInt(text, 2)`를 사용한다.

## 11. 주의할 점

- `1 << N`을 사용할 때 `N`이 너무 크면 `int` 범위를 벗어날 수 있다.
- `N`이 31 이상이면 `long`과 `1L << N`을 고려한다.
- `^`는 거듭제곱이 아니라 XOR 연산이다.
- `~`는 모든 비트를 반전하므로 음수 결과가 나올 수 있다.
- 비트 위치는 보통 0번부터 시작한다.
- 부분집합 순회는 `2^N`개를 확인하므로 `N`이 커지면 사용할 수 없다.

## 12. 다른 방법이 있는데도 비트마스킹을 사용하는 이유

비트마스킹은 배열, `Set`, boolean 배열로도 풀 수 있는 문제를 굳이 숫자 하나로 표현하는 방법이다. 그렇다면 왜 비트마스킹을 사용할까?

- 여러 개의 참/거짓 상태를 정수 하나에 저장할 수 있어 상태 관리가 간단하다.
- 두 상태를 `&`, `|`, `^` 같은 연산 한 번으로 빠르게 비교하거나 변경할 수 있다.
- 방문 상태나 선택 상태를 배열 대신 정수로 표현하므로 메모이제이션의 상태를 비교하고 저장하기 편하다.
- `Set`처럼 객체를 만들고 값을 비교하는 비용을 줄일 수 있어, 상태가 많아지는 완전 탐색·비트 DP에서 유리하다.
- 단, 원소 수가 작고 각 상태가 0/1로 나뉘는 경우에 적합하다. 원소 수가 크거나 상태가 여러 종류라면 배열·`Set`·`Map`이 더 읽기 쉽고 적절할 수 있다.

예를 들어 20개 도시의 방문 여부를 `boolean[20]`으로 관리할 수도 있다. 하지만 방문 상태 전체를 메모이제이션해야 한다면 `visited`를 하나의 정수로 표현하는 편이 `dp[현재 도시][visited]` 형태로 저장하기 쉽다. 반대로 방문 여부만 한 번 확인하고 상태를 저장하지 않는 문제라면 boolean 배열이 더 이해하기 쉬울 수 있다.

즉, 비트마스킹은 무조건 빠른 만능 도구가 아니라 **작은 개수의 0/1 상태를 하나의 값으로 묶어 반복적으로 비교·저장해야 할 때 선택하는 방법**이다.

## 13. 어떤 코테 문제에서 비트마스킹을 의심해야 할까?

다음과 같은 느낌의 문제가 나오면 비트마스킹을 먼저 떠올려 볼 수 있다.

- 원소의 개수가 작고, 각 원소를 선택하거나 선택하지 않는 모든 경우를 확인해야 한다.
- 방문 여부, 사용 여부, 포함 여부처럼 각 항목의 상태가 `예/아니오` 두 가지뿐이다.
- “사용한 숫자”, “방문한 도시”, “선택한 사람”, “켜진 기능”을 여러 개 기억해야 한다.
- 현재 상태를 배열이나 `Set`으로 저장하면 상태 비교가 복잡해지지만, 각 항목을 0과 1로 표현할 수 있다.
- 문제에서 부분집합, 모든 조합, 선택된 원소의 개수, 중복 없는 방문 상태를 반복해서 확인한다.

### 예시 1: 모든 메뉴 조합 확인하기

> 메뉴가 3개 `[김밥, 라면, 돈가스]` 있다. 손님이 주문할 수 있는 모든 메뉴 조합을 출력하라.

메뉴마다 “주문한다/주문하지 않는다” 두 가지 선택이 있으므로 전체 경우의 수는 `2^3 = 8`개이다. 이때 각 메뉴의 선택 여부를 비트 하나로 표현할 수 있다.

```text
비트 위치:  2       1       0
메뉴:      돈가스   라면     김밥

101 → 돈가스와 김밥을 주문
010 → 라면만 주문
000 → 아무 메뉴도 주문하지 않음
```

이처럼 문제에서 원소 수가 작고 “모든 선택 조합”을 확인하라고 하면, `mask`를 0부터 `(1 << n) - 1`까지 순회하는 방법을 의심한다.

### 예시 2: 방문한 도시를 기억하는 문제

> 4개의 도시를 한 번씩 방문해야 한다. 현재 도시와 지금까지 방문한 도시를 이용해 다음 이동을 결정하라.

방문 여부는 도시마다 방문/미방문 두 상태뿐이다. 따라서 4개 도시의 방문 상태를 `0000`부터 `1111`까지 하나의 정수로 저장할 수 있다.

```text
visited = 0101
         ↑ ↑
       2번 0번 도시를 방문함
```

문제에서 “이미 방문했는가?”, “모든 도시를 방문했는가?”, “이 방문 상태를 이미 계산했는가?”를 자주 확인한다면 `visited` 비트마스크와 `dp[현재 위치][visited]`를 의심한다.

### 예시 3: 기능을 켜고 끄는 문제

> 여러 기능이 있고, 특정 기능들을 켰을 때의 비용을 계산한다. 기능을 켜고 끄는 모든 경우를 확인하라.

각 기능을 켜짐/꺼짐으로 표현할 수 있으므로 비트마스크가 잘 맞는다. 예를 들어 `1011`은 0번, 1번, 3번 기능이 켜진 상태이다. 문제에서 “선택된 기능의 수”, “특정 기능이 켜져 있는지”, “한 기능만 추가로 켜기” 같은 표현이 나오면 다음 연산을 떠올린다.

```text
1 << i       → i번째 기능을 켤 위치를 만든다.
mask & bit   → i번째 기능이 켜져 있는지 확인한다.
mask | bit   → i번째 기능을 켠다.
Integer.bitCount(mask) → 켜진 기능의 개수를 센다.
```

단, 원소 수가 너무 크면 모든 상태가 `2^N`개로 늘어나므로 비트마스킹 완전 탐색을 사용할 수 없다. 먼저 `N`의 범위와 시간 복잡도를 확인해야 한다.
